# Feature 实施路线

依据当前全部13份 spec，规则 `0.3`、配置 `baseline-1`，含MongoDB运行架构修订。F01—F04A已完成；F04A按已验证用例范围验收，已知限制见其记录。F05已完成；F06—F09待实施。API使用MongoDB持久化入口。

feature以一个会话可完成实现、验证的交付能力为单位，内部模块合并实施，不机械拆成多个会话。实施前按当时仓库复核工作量；若确需拆分，保留独立验收并更新依赖，不能把未验证范围标为完成。

## 共同完成条件

每项完成代码、必要测试或操作验证，并补充实现入口、验证命令与结果、规则版本及偏差，更新索引状态。固定输入验证公式和原子性；随机竞争验证合法范围、总量与实际记录，不断言固定赢家。历史读取事实，不靠重新执行策略重建。

当前仅启用本阶段能力，未实现机制加载时明确拒绝。集合、配方、策略、市场与阶段接口保留扩展入口，避免把food、20人、一家企业和一个区域写成永久模型限制；无需提前构建复杂插件框架。

## 暂不直接实现的能力

以下内容须先补齐spec或升级规则，再另建feature：混合质量市场的接受集合、替代关系与联合分配；人员物品栏仓库的移动死亡交割语义；不可拆分配方的在制品、成本及报废回收；双向申报的禁止自配对算法；个人食品生产资格制度；股权冻结的账簿承载；市场重估的权益分录；组织成立解散的资产清理；非基准手动干预的授权与生效冲突规则。

动态区域生成销毁、多货币、多国家、融资分红、辞退辞职、自发创业、工资形成、管理岗位、复杂债务、个人能力差异、私人关系、家庭年龄生育、背包容量、区域内通用物流及建筑交易等“当前阶段不考虑”的机制不列为本轮任务。数据模型可扩展不表示已经支持。

F06工具价值消耗、F08旅行计时及搬运时长/中断位置如无法从现有spec唯一确定，实施前先作小范围规范补充，不能成为隐藏默认行为。未来机制不能通过删除旧规则掩盖问题。
