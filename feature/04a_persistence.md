# F04A MongoDB持久化与有界内存

状态：已完成（2026-10-31，按已验证用例范围验收）。依据：规则0.3的MongoDB运行架构修订 / baseline-1。依赖：F04；前置于F05。

## 目标与来源

将完整历史移出内存，提供重启后可查、可恢复且提交原子的MongoDB运行服务。取代F04仅内存保存及序列化大小计费的实现边界，保留F04当时的验收记录，不回写历史方案。

来源：[运行架构与持久化提交](../spec/world-rules/07_runtime_observation.md)、[结算与历史](../spec/world-rules/06_settlement_history.md)、[配置规范](../spec/content-config/01_configuration.md)。不改变经济规则和策略公式。

## 实施路径

1. 独立存储接口与MongoDB适配器，提供可复用的本地副本集启动配置、连接配置及事务能力检查。明确MongoDB和驱动版本；凭据不进入仓库、场景及导出。
2. 按运行、回合、事件、指标及恢复状态设计集合、唯一键和查询索引。文档按大小拆分，禁止单运行无限增长文档。模式及配置显式版本化，旧F04配置转换须有明确入口和规则，不隐式补默认字段。
3. 在候选状态上计算回合，以事务持久化回合全部事实、继续运行所需状态、请求去重结果和提交游标后再发布。支持单运行写入所有权及过期写入防护；提交不明时查证，不重新抽取已提交随机结果。
4. 改造核心及运行服务的历史持有方式，清除随回合数增长的内存列表、历史任务和无界请求缓存。策略只留必需窗口；历史、去重记录和已完成任务按需访问数据库。当前世界随主体和库存规模增长的成本须独立测量，不能宣称全部内存恒定。
5. 实现最后已提交状态恢复，包含记忆、未来任务、批次、参数与配方版本、参考价窗口及调度状态；重启后默认暂停。历史分页、筛选、关联查询与流式导出供F05使用，记录接口兼容性变化。
6. 配置内存、缓存、在途批次、存储容量和保留范围边界；超限或数据库不可用时在安全边界暂停，保存失败证据，不删承诺历史、不回退内存运行。

## 已验证用例

当前清单仅保留实际执行并通过的用例；暂时移除未验证用例，不改变spec约束，也不将相关能力视为已经验证。

- 基准和五个变体各720回合，逐回合验证现金发行守恒、资产负债平衡及居民现金流。
- 同请求重复创建返回原运行，配置冲突拒绝；10个存储实例并发提交同一单步请求，仅推进一次。
- 事务中注入异常，回合游标保持不变；提交确认后模拟响应丢失，查回原结果，重试不再推进。
- 重新建立存储实例后快照一致，默认不运行；在第240回合重新建立实例后继续完成720回合。
- 分页遍历720回合并进行账实校验；执行主体、物品、市场筛选查询及NDJSON导出行数检查。
- 使用真实MongoDB副本集，记录运行、恢复读取、分页耗时及进程峰值内存；这些测量不证明长期内存有界。

## 范围与扩展

只交付MongoDB持久化、提交恢复与有界历史访问，不同时实现F05界面或F06经济机制。数据库备份运维、跨地域容灾和运行迁移另行规划；重启恢复不等于固定种子重放。实施若发现无法一次验证的范围，先调整交付边界和依赖，不标记未验证能力完成。

完成时填写：模式与接口入口、部署命令、故障注入证据、恢复及性能测量。

## 实现与验证记录（2026-10-31）

规则0.3 MongoDB架构修订 / baseline-1；依赖F04。已新增`Persistence.cs`独立IRunStore/MongoRunStore、`Recovery.cs`恢复状态及API持久化入口。本记录不将未验证范围标记为完成。

- MongoDB.Driver固定3.5.2；实测本机MongoDB 8.2副本集eco-rs，独立27018端口，不修改已有27017服务。部署脚本与compose见根目录，连接仅来自环境配置。
- 集合runs、requests、turns、chunks，回合及分片复合唯一索引；主体、物品、市场索引。JSON金额为十进制字符串无损编码，负载以1MiB BSON binary分片。恢复world-1、持久化mongo-1、导出runtime-2-ndjson明确版本化。
- 候选世界从已提交恢复状态建立，不携带累计事件、历史和完成任务；策略仅保存当前记忆、未来任务及成交窗口。事务同时保存完整回合、恢复状态、去重结果和游标；写入租约与revision校验提供过期写入防护。完整恢复状态目前保留每个边界，数据库容量仍会增长。
- `dotnet test -c Release --filter FullyQualifiedName~PersistenceTests`真实副本集通过：事务中注入异常回滚、确认后抛出响应丢失查回原结果、重新建立存储实例查询恢复、10个实例同请求只提交一次、分页及NDJSON导出。
- `dotnet test -c Release --filter FullyQualifiedName~PersistenceAcceptanceTests`六场景720回合曾6/6通过；逐回合发行守恒、账实与居民现金流验证，240回合重建实例比较快照一致。随后加入租约防护，须以最终全量测试结果为准。
- 硬件沿用F04本机Windows、i7-12700、20逻辑处理器。该轮单场720回合约12.7—19.9秒，恢复5—14ms，20回合分页11—54ms；测试进程累计峰值约841MiB。测试记录显示托管占用受驱动及同进程其他测试影响，不能据此证明长历史内存恒定。数据库storageSize尚受WiredTiger检查点影响，早期出现16384等无代表性数值，不作为容量结论。
- 全套测试曾因旧F04全历史测试保留内存导致新运行触发进程预算而失败；验收场景现显式使用2GiB内存边界并关闭并行测试，未改变经济参数。不能以此推断baseline默认预算已验证适用。

已知实现边界（非验收用例）：数据库实际容量准入、失败证据持久化、跨实例调度所有权和暂停屏障、日聚合兼容接口仍需完善。当前PageSize策略字段未与查询准入统一，查询按回合数限制但仍需字节上限。创建元数据与去重签名仍需大配置分片。IRunStore未覆盖全部查询接口。恢复输入尚需更严格的完整模式校验。旧SimulationRun仅供F04历史测试，不能作为持久化不可用时的运行后备。上述限制保留为后续改进事项，不属于本次已验证范围。

最终阶段验证：`dotnet test -c Release --nologo`为39/39通过，约2分15秒，包含六场景720回合及原有32项测试。随后将Mongo适配器移至独立`src/EcoSimulator.Persistence`项目以保持核心无数据库依赖；迁移后`dotnet build -c Release --nologo`零警告零错误，`--filter FullyQualifiedName~PersistenceTests`再次通过。独立项目迁移未修改结算逻辑。最终验收场景显式内存预算2GiB；未完成项仍如上，不因现有测试全绿而解除。
