# F04A MongoDB持久化与有界内存

状态：待实施。依据：规则0.3的MongoDB运行架构修订 / baseline-1。依赖：F04；前置于F05。

## 目标与来源

将完整历史移出内存，提供重启后可查、可恢复且提交原子的MongoDB运行服务。取代F04仅内存保存及序列化大小计费的实现边界，保留F04当时的验收记录，不回写历史方案。

来源：[运行架构与持久化提交](../spec/world-rules/07_runtime_observation.md)、[结算与历史](../spec/world-rules/06_settlement_history.md)、[配置规范](../spec/content-config/01_configuration.md)。不改变经济规则和策略公式。

## 实施路径

1. 独立存储接口与MongoDB适配器，提供可复用的本地副本集启动配置、连接配置及事务能力检查。明确MongoDB和驱动版本；凭据不进入仓库、场景及导出。
2. 按运行、回合、事件、指标及恢复状态设计集合、唯一键和查询索引。文档按大小拆分，禁止单运行无限增长文档。模式及配置显式版本化，旧F04配置转换须有明确入口和规则，不隐式补默认字段。
3. 在候选状态上计算回合，以事务持久化回合全部事实、继续运行所需状态、请求去重结果和提交游标后再发布。支持单运行写入所有权及过期写入防护；提交不明时查证，不重新抽取已提交随机结果。
4. 改造核心及运行服务的历史持有方式，清除随回合数增长的内存列表、历史任务和无界请求缓存。策略只留必需窗口；历史、去重记录和已完成任务按需访问数据库。当前世界随主体和库存规模增长的成本须独立测量，不能宣称全部内存恒定。
5. 实现最后已提交状态恢复，包含记忆、未来任务、批次、参数与配方版本、参考价窗口及调度状态；重启后默认暂停。历史分页、筛选、关联查询与流式导出供F05使用，记录接口兼容性变化。
6. 配置内存、缓存、在途批次、存储容量和保留范围边界；超限或数据库不可用时在安全边界暂停，保存失败证据，不删承诺历史、不回退内存运行。

## 验收与验证

- 基准和五个变体各720回合，保留原有守恒、账实、版本及现金流验证；数据库事实与API快照一致。
- 并发重复创建、单步及恢复请求只提交一次；多实例不得同时推进同一运行。唯一索引验证重复回合及请求冲突。
- 在事务前、中、确认后注入断连、取消及进程终止；重启只能看到完整已提交边界。模拟提交成功但响应丢失，重试查回原结果，不能再次推进或改变随机结果。
- 重启后查询历史、流式导出、显式继续成功；恢复状态与关闭前已提交状态一致。跨冲击、死亡、跨日、连续休息及未来任务边界验证记忆完整。比较状态和规则合法性，不要求重新运行策略复现同一随机未来。
- 长历史及并发查询实测证明历史不会线性占用内存；覆盖超16MiB回合数据拆分、分页关联完整、导出取消与背压、BSON/API大整数往返及不兼容模式拒绝。
- 小预算、存储不足和数据库中断安全暂停，无半笔交易或静默删史；记录当前世界、缓存、在途提交、进程峰值与数据库大小，不能仅报告序列化大小。
- 使用真实MongoDB副本集集成测试，记录硬件、规模、运行耗时、重启恢复耗时、分页查询延迟及峰值内存。扩大历史长度与主体数量分别测量，不预设未经验证的吞吐目标。

## 范围与扩展

只交付MongoDB持久化、提交恢复与有界历史访问，不同时实现F05界面或F06经济机制。数据库备份运维、跨地域容灾和运行迁移另行规划；重启恢复不等于固定种子重放。实施若发现无法一次验证的范围，先调整交付边界和依赖，不标记未验证能力完成。
